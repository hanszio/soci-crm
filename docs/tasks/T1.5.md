# Objetivo
Cerrar la fase 1 con E2E automatizados de todo lo nuevo y CI en verde.

# Contexto
- `scripts/e2e-selftest.mjs` conduce guiones `tests/e2e/*.md` contra la app con mocks. Mocks: `src/app/api/dev/{wa-mock,ai-mock,google-mock,zoom-mock}`. T1.1 añadió `ai-mock/v1/embeddings`; T1.6 la API `/api/settings/ai`.
- Sesión: el script hace sign-up/sign-in con `origin` y guarda la cookie (ver función `api()`).

# Archivos
- Modifica: `scripts/e2e-selftest.mjs`, `src/server/dev/ai-mock.ts` (respuestas por escenario), `tests/e2e/us-fase1.md` (nuevo), `.github/workflows/ci.yml` (si T0.5 ya está: solo asegurar que el job e2e exporta `AGENT_DELAY_MODE=instant` y `AGENDA=on`).
- Prohibido: `src/**` salvo `src/server/dev/**` y `src/app/api/dev/**`.

# Escenarios (cada uno con su check OK/FAIL)
1. Ajustes → IA: probar con compat→ai-mock OK; clave inválida → 422 `provider_rejected`; guardar; `GET` sin clave; rol no admin → 403; `DELETE` vuelve a plataforma.
2. Fallback: ai-mock devuelve 402 para un modelo y 200 para otro (soporta cabecera o nombre de modelo para decidir); con `AI_MODEL=compat/falla` y `AI_FALLBACK=compat/responde` el agente responde igual y `usage_event` tiene la fila fallida y la exitosa.
3. Retraso humano: con `AGENT_DELAY_MODE=human` y `delay_min_sec=5`, tras un inbound el wa-mock recibe typing y luego el texto; con `instant` la respuesta es inmediata.
4. Handoff tras cita: flujo completo de agenda con `book_slot` → `handoff_reason = cita_agendada` → siguiente inbound no responde.
5. Modalidad: dos modalidades permitidas → el agente pregunta → cita presencial con dirección.

# Criterios de aceptación
- `pnpm test:e2e` en verde localmente y en CI; cada escenario nuevo aparece en la salida con su OK.

## Reglas duras (obligatorias)

1. No ejecutes `pnpm db:generate`. Cambia solo `src/lib/db/schema/*.ts`; QA genera la migración al integrar.
2. Tablas nuevas en `src/lib/db/schema/<feature>.ts` + `export * from "./schema/<feature>"` en `src/lib/db/schema.ts`.
3. Toda query de dominio usa `scoped(schema.tabla.organizationId, organizationId, ...)` de `src/lib/db/tenant.ts`. Toda tabla nueva lleva `organization_id NOT NULL` con FK cascade a `organization`.
4. Secretos cifrados con `src/lib/crypto`. Nunca al cliente ni a logs.
5. Terceros nuevos = conector opcional tras bandera de entorno, apagado por defecto, 404 cuando está apagado.
6. Conversaciones `is_test` jamás tocan APIs reales. No toques ese guardrail.
7. Solo tocas los archivos listados en este brief. Si necesitas otro, dilo en el PR y para.
8. Gate antes de abrir PR: `pnpm typecheck && pnpm lint && pnpm test && pnpm build` en verde + tests unitarios de tu código + guion E2E en `tests/e2e/<us>.md` si hay flujo de usuario.
9. IDs con `newId("<entidad>")` registrando el prefijo donde viven los demás.
10. Español en UI, comentarios y docs; código y nombres de tablas en inglés.
11. Al terminar: commit (Conventional Commits en español), push, `gh pr create --base phase/1 --fill`, y escribe `DONE <número de PR>`. Si te bloqueas: `BLOCKED: <motivo>`.
