# Objetivo
Cuando el agente agenda una cita con éxito, la conversación pasa a un humano automáticamente (motivo `cita_agendada`), el lead se mueve a la etapa de cliente, y el bot deja de responder.

# Contexto
- `src/server/ai/pipeline.ts`: en la rama `book_slot`, `bookSlot()` (`src/server/agenda/agent.ts`) devuelve `AgendaTurn { ok, text }`; si `turn.ok` hoy solo entrega el texto y publica `conversation.updated`. `applyHandoff(conversationId, organizationId, reason)` existe en el mismo archivo y ya silencia al agente (`handoff_at`). `moveLeadToStage` y `resolveStage` también están ahí.
- Etapas: tabla `pipeline_stage` con `name` y `position`; no hay bandera "ganada". Usa la última etapa cuyo nombre contenga "cliente" (case-insensitive) o, si no existe, no muevas.
- `handoffReason` es texto libre en `conversation`; la bandeja muestra el motivo (`src/components/inbox/*`): añade la etiqueta "Cita agendada" para ese motivo.

# Archivos
- Modifica: `src/server/ai/pipeline.ts` (solo la rama `book_slot` tras `turn.ok`), `src/server/agenda/agent.ts` (que `AgendaTurn` incluya `bookingId` cuando `ok`), `src/server/ai/prompts.ts` (una regla: "tras confirmar la cita, despídete en la misma respuesta; un asesor continúa"), `src/components/inbox/*` (etiqueta del motivo), `tests/unit/handoff-cita.test.ts`, `tests/e2e/us-agenda.md`, `scripts/e2e-selftest.mjs` (escenario nuevo).
- Prohibido: `src/lib/ai/**`, `src/server/jobs/**`, `drizzle/**`.

# Especificación técnica
1. `book_slot` con `turn.ok`: `deliverReply(turn.text)` → mover lead a la etapa "cliente" si existe → `applyHandoff(conversationId, organizationId, "cita_agendada")` → publicar `conversation.updated`. Si `turn.ok = false` (hueco ocupado), el agente sigue activo y ofrece alternativas como hoy.
2. Cancelar un job pendiente de la conversación al hacer handoff: llama `cancelForConversation` de `src/server/jobs/queue.ts` dentro de `applyHandoff` (import permitido; no modifiques la cola).
3. La bandeja muestra "Cita agendada · atiende un asesor" cuando `handoff_reason = 'cita_agendada'`.

# Criterios de aceptación
1. E2E con mocks: conversación → `offer_slots` → `book_slot` → cita creada, `handoff_at` no nulo, `handoff_reason = 'cita_agendada'`, lead en etapa cliente; el siguiente mensaje del cliente NO genera turno ni job.
2. Test unitario del mapeo de etapa (existe/no existe "cliente").
3. Gate verde.
