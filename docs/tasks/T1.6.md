# Objetivo
Pantalla **Ajustes → IA** para que cada organización elija proveedor, pegue su propia clave (cifrada) y defina modelo principal y modelo juez, con botón "Probar conexión". El agente y el Laboratorio usan esa configuración; si no hay, usan las variables de entorno de la plataforma.

# Contexto
- T1.1 dejó `src/lib/ai/registry.ts` con `resolveModel(id, { organizationId })` que consulta `getOrgAiOverride(organizationId)` en `src/lib/ai/org-override.ts` (hoy devuelve `null`). Esta tarea implementa esa función y su UI.
- Patrón a copiar: `src/server/whatsapp/credentials.ts` + `src/app/api/settings/whatsapp/{route,test}/route.ts` + `src/components/settings/whatsapp-wizard.tsx` (token cifrado con `src/lib/crypto`, "probar antes de guardar", solo últimos 4 caracteres visibles).
- Menú de Ajustes: `src/app/(app)/settings/*` (pestañas WhatsApp, Marca, Plantillas, Equipo, Agenda). Añadir pestaña **IA**.
- Solo `owner` y `admin` pueden ver y editar esta pantalla (`requireSession().role`).

# Archivos
- Crea: `src/lib/db/schema/ai-settings.ts`, `src/server/ai-settings/{store,test}.ts`, `src/app/api/settings/ai/route.ts` (GET/PUT/DELETE), `src/app/api/settings/ai/test/route.ts` (POST), `src/app/(app)/settings/ai/page.tsx`, `src/components/settings/ai-settings-client.tsx`, `tests/unit/ai-settings/*.test.ts`, `tests/e2e/us-ajustes-ia.md`.

- Prohibido: `src/lib/ai/{index,registry,fallback}.ts`, `src/server/ai/**`, `drizzle/**`.

# Especificación técnica
1. Tabla `ai_settings(id text pk, organization_id text unique fk organization cascade, provider text enum anthropic|openai|google|openrouter|compat, api_key_cipher text, api_key_iv text, api_key_tag text, api_key_last4 text, base_url text null, model text, judge_model text null, updated_by text fk user, created_at, updated_at)`.
2. Proveedores y valores por defecto en un catálogo `src/lib/ai/providers.ts` (exportado para la UI): nombre visible, URL donde sacar la clave, prefijo esperado de la clave (`sk-ant-`, `sk-`, `AIza`, `sk-or-`), modelos sugeridos (Anthropic: claude-sonnet-4-5, claude-haiku-4-5; OpenAI: gpt-5, gpt-5-mini; Google: gemini-2.5-pro, gemini-2.5-flash; OpenRouter: anthropic/claude-sonnet-4.5, openai/gpt-5-mini; compat: campo libre + base URL obligatoria, ejemplos Groq/DeepSeek/Ollama/OpenCode Zen).
3. `POST /api/settings/ai/test`: con el body (sin guardar) construye el modelo vía `resolveModel` usando un override temporal y hace una llamada mínima (`chatText`, máx 20 tokens, timeout 20 s). Responde `{ ok, latencyMs, model }` o `{ ok:false, error }` con el mensaje del proveedor recortado (401 → "clave inválida", 402 → "sin créditos", 404 → "modelo no existe").
4. `PUT /api/settings/ai`: valida con Zod, cifra la clave, guarda `last4`; si el body no trae `apiKey` conserva la existente (permite cambiar solo el modelo). `DELETE` borra la fila → la organización vuelve a las claves de plataforma. `GET` nunca devuelve la clave, solo `last4`.
5. `getOrgAiOverride(organizationId)`: lee la fila, descifra y devuelve `{ provider, apiKey, baseUrl, model, judgeModel }` o `null`. Caché en memoria 60 s por organización, invalidada en PUT/DELETE.
6. UI: selector de proveedor con ayuda y enlace a "dónde saco la clave", campo clave (password, muestra "…${last4}" si ya existe), base URL (solo compat), modelo principal (select con sugeridos + "otro"), modelo juez (opcional), botones **Probar conexión** (muestra latencia y modelo) y **Guardar** (deshabilitado hasta que la prueba pase o si no cambió la clave), enlace **Volver a la configuración de la plataforma** (DELETE con confirmación). Indicador arriba: "Usando: tu clave de Anthropic (…abcd)" o "Usando: clave de la plataforma".
7. Página Agente (`src/app/(app)/agent`): NO se toca; pero si `isAiConfigured()` es falso para la org, el banner existente debe enlazar a Ajustes → IA (verificar que el texto del banner lo permita sin modificar `src/server/ai/**`; si requiere cambio ahí, reportarlo en el PR y no hacerlo).

# Criterios de aceptación
1. Con la plataforma SIN claves de entorno, una organización configura Anthropic en Ajustes → IA, prueba, guarda y el Laboratorio corre con esa clave (E2E con ai-mock apuntado vía proveedor compat).
2. Dos organizaciones con proveedores distintos no se mezclan (test unitario de `getOrgAiOverride` + `scoped`).
3. `GET /api/settings/ai` jamás devuelve la clave; en BD solo hay cifrado; los logs no la muestran.
4. Rol `agent` recibe 403 en GET/PUT/DELETE y no ve la pestaña.
5. Probar con clave inválida → mensaje claro "clave inválida"; con 402 → "sin créditos".
6. Gate verde; `pnpm db:generate` produce solo `ai_settings` (no commitear la migración).

## Reglas duras (obligatorias)
