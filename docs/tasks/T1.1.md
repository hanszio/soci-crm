# Objetivo
Reemplazar el adaptador único OpenRouter-compatible por Vercel AI SDK con registro de proveedores (Anthropic, OpenAI, Google, OpenRouter, compatible-OpenAI), cadena de fallback con circuit breaker, embeddings y medición de uso por organización, sin cambiar la firma pública `chatJson<T>`.

# Contexto
- `src/lib/ai/index.ts` es la ÚNICA frontera con el proveedor (constitución II de Vocero). Expone `chatJson<T>(schema, messages, opts?: { model?, judge?, timeoutMs? }): Promise<ChatJsonResult<T>>` e `isAiConfigured()`. Implementa reintentos (3), extracción robusta de JSON y errores tipados `not_configured | provider_error | invalid_output`. Hoy llama a `${OPENROUTER_BASE_URL}/v1/chat/completions`.
- Consumidores que NO deben cambiar: `src/server/ai/pipeline.ts` (agente), `src/server/lab/{runner,judge}.ts` (Laboratorio), `src/server/agenda/*`.
- Env actual en `src/lib/env.ts`: `OPENROUTER_API_TOKEN`, `OPENROUTER_BASE_URL`, `OPENROUTER_MODEL`, `OPENROUTER_JUDGE_MODEL`. Deben seguir funcionando (compatibilidad): si `AI_MODEL` no existe, se deriva `openrouter/<OPENROUTER_MODEL>` con `OPENROUTER_API_TOKEN`.
- El self-test E2E usa el mock `src/app/api/dev/ai-mock/v1/chat/completions` (OpenAI-compatible). Debe seguir en verde: el proveedor `compat` apuntando a `AI_COMPAT_BASE_URL=http://localhost:3000/api/dev/ai-mock` reproduce el flujo.
- Motivo de negocio: hoy un 402 de OpenRouter deja al agente mudo (visto en producción el 2026-09-03). Con fallback, pasa al siguiente proveedor.

# Especificación técnica
1. Dependencias: `ai`, `@ai-sdk/anthropic`, `@ai-sdk/openai`, `@ai-sdk/google`, `@openrouter/ai-sdk-provider`, `@ai-sdk/openai-compatible`. Versiones estables actuales (verifica con `pnpm view <pkg> version`).
2. Env nuevo (todas opcionales): `AI_MODEL` (`proveedor/modelo`), `AI_JUDGE_MODEL`, `AI_GATE_MODEL`, `AI_EMBED_MODEL` (default `openai/text-embedding-3-small`), `AI_FALLBACK` (lista separada por comas de `proveedor/modelo`), `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`, `OPENROUTER_API_KEY` (alias de `OPENROUTER_API_TOKEN`), `AI_COMPAT_BASE_URL`, `AI_COMPAT_API_KEY`, `AI_COMPAT_NAME` (default `compat`). Validar en `env.ts` con Zod; `isAiConfigured()` es true si hay al menos un modelo resoluble con su clave.
3. **Override por organización (contrato para T1.6)**: `registry.ts` exporta `resolveModel(id, ctx?: { organizationId?: string })`. Si `ctx.organizationId` viene, antes de usar las claves de entorno consulta `getOrgAiOverride(organizationId)` (función en `src/lib/ai/org-override.ts`, que en esta tarea devuelve `null`; T1.6 la implementa leyendo la tabla `ai_settings`). El override tiene la forma `{ provider, apiKey, baseUrl?, model?, judgeModel? }` y, si existe, reemplaza clave y modelo para esa organización. `chatJson`/`chatText`/`embed` propagan `opts.organizationId` al registro.
4. `registry.ts`: `createProviderRegistry({ anthropic, openai, google, openrouter, [AI_COMPAT_NAME]: createOpenAICompatible({ baseURL: AI_COMPAT_BASE_URL, apiKey }) })` construido perezosamente. `resolveModel(id: string): LanguageModel` y `resolveEmbedding(id: string): EmbeddingModel`. Error tipado `not_configured` si falta la clave del proveedor pedido.
5. `fallback.ts`: `withFallback(models: string[], fn: (model) => Promise<T>)`. Circuit breaker en memoria por id de modelo: 3 fallos consecutivos (HTTP 402/429/5xx o timeout) → abierto 5 min; medio-abierto tras el plazo. Errores 400/401/403 no abren el breaker (son de configuración) pero sí pasan al siguiente. Devuelve el resultado del primer modelo que responde; si todos fallan, `provider_error` con el detalle de cada intento.
6. `index.ts`: conservar EXACTAMENTE la firma de `chatJson<T>` y los tipos exportados. Implementación: `generateObject({ model, schema, messages, maxRetries: 0, abortSignal })`; si el proveedor rechaza salida estructurada (`NoObjectGeneratedError` o similar), reintentar con `generateText` + la extracción robusta actual (`extractJson`). Mantener los 3 intentos con la instrucción STRICT del segundo intento en adelante. Añadir `chatText(messages, opts)` (respuesta libre; para visión y resúmenes futuros; acepta partes de imagen) y `embed(texts: string[]): Promise<number[][]>` con `embedMany` en lotes de 64. `opts.organizationId?: string` nuevo y opcional (solo se usa para medir uso).
7. `usage.ts` + tabla `usage_event(id text pk, organization_id text null fk organization cascade, model text, kind text chat|judge|gate|embed|text, tokens_in int, tokens_out int, latency_ms int, ok boolean, error text null, created_at timestamptz default now())`, índices `(organization_id, created_at)` y `(created_at)`. Escribir una fila por llamada (best-effort, nunca lanza). Exportar `monthlyUsage(organizationId, month)`.
8. Mock: `POST /api/dev/ai-mock/v1/embeddings` devuelve vectores deterministas de 1536 dimensiones por hash del texto, tras el mismo gate `src/lib/dev-guard.ts` (404 en producción).
9. Compatibilidad: sin `AI_MODEL`, derivar de `OPENROUTER_MODEL`; `OPENROUTER_BASE_URL` distinto del default se mapea al proveedor `compat` (así el self-test actual con ai-mock sigue igual sin cambiar variables).
10. README: tabla de proveedores, ejemplos de `AI_MODEL` y `AI_FALLBACK`, nota de que Anthropic no es OpenAI-compatible y por eso existe el registro.

# Criterios de aceptación
1. `pnpm test:e2e` (self-test con ai-mock) en verde sin cambiar las variables de mock existentes.
2. Test: modelo primario responde 402 tres veces → se usa el segundo de `AI_FALLBACK`; el breaker del primero queda abierto y un cuarto intento no lo llama (mock cuenta llamadas).
3. Test: salida no-JSON en el primer intento → segundo intento con instrucción STRICT → si sigue mal, `invalid_output` tipado; `pipeline.ts` no cambia.
4. Test: `resolveModel("anthropic/claude-sonnet-4-5")` sin `ANTHROPIC_API_KEY` → `not_configured`; con clave → instancia del proveedor Anthropic.
5. `usage_event` recibe una fila por llamada con tokens del proveedor (o 0 si el proveedor no los reporta) y `ok=false` con `error` cuando falla.
6. `pnpm db:generate` produce exactamente una tabla nueva (`usage_event`); NO commitear la migración (QA la genera).
7. Gate: `pnpm typecheck && pnpm lint && pnpm test && pnpm build` verde; `pnpm build` sin warnings de edge runtime.
